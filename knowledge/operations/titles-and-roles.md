# Members and project roles

## Everyone is a Member

There are no org titles and no tiers. Anyone who joins Novawerk is a
**Member**, and every Member is hands-on: we build the projects and ship
the work.

Maintainers run Novawerk: they review pitches, approve outgoing email, run
the task board and see the whole admin panel (NB-ADR-0014). That is a role,
not a rank. It says what someone is trusted to do, not who they are. The
members of a project's team see that project in the admin panel.

## Project roles

Inside a project, two things describe a contributor.

### Initiator (exactly one per project)

The person who brought the idea and now owns its direction. Exactly one
per project. The Initiator is the answer to *whose project is this?* —
the named person responsible for whether the project moves. When a
project pitch is accepted, the person who pitched it becomes its Initiator.

### Function (one or more per contributor)

What kind of work a contributor does on the project. The seed set:

- PM
- Developer
- Designer
- Researcher
- PR / Marketing
- Operations

The list grows as projects need new functions. A contributor may carry
more than one function on a small project, but each function should still
belong to exactly one named person at any given time.

People with no function on a project are not formally on its team. They
are watching, and the [community pledge](../culture/principles/pledge.md)
applies to them the same as to anyone else.

## What's expected of every Member

- Finishes what they take on: one artifact, one named owner, one done-by
  date, a plain yes or no on done.
- Writes load-bearing decisions down where everyone can read them, not in DMs.
- Represents Novawerk accurately when no one else is in the room.

## History

Until October 2026 Novawerk used three org titles (Werker, Architect,
Ambassador). We dropped them to keep things simple: the work, not the
title, is what matters.
