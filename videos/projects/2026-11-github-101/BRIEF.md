# Novawerk 101 · GitHub 是什么，我们怎么用它 · 2026-11

Novawerk 101 的第一条：给**不写代码的项目方**看的讲解片。共用规则见 `../../BRAND.md`，这里只写这条
视频自己的事。

- 起因（创始人，2026-11-17）：和项目方协作时发现，很多人不知道 GitHub 是什么，也不知道怎么操作。
- 给谁看：带着想法来的项目方和他们的伙伴，不写代码，第一次被邀请进一个仓库。
- 发在哪：直接发给项目方（微信等），放进 onboarding 材料；中文版也发小红书；英文版给不说中文的伙伴。
- 规格：**中文版和英文版各一条**，3:4（1080×1440），中文 139 秒、英文 135 秒，合成人声旁白加字幕，不出 9:16。
- 因为要发小红书：画面、字幕、发布文案里**不放任何网址**，窗口的地址栏不画；不引导、不招人。
- 成片：`out/github-101_3x4.mp4`（中文）、`out/github-101_en_3x4.mp4`（英文）；封面 `out/cover_3x4.png`、
  `out/cover_en_3x4.png`；发布文案 `POST.md`。

## 口气和内容（创始人 2026-11-17 看过第一版后定的）

第一版是「念稿子 + 演示怎么在 GitHub 上点」。创始人的意见：「感觉有点机械」；要「非常非常口语化」，
像播客，像这样开头：*Welcome to Novawerk 101, basic stuff that get you to work with novawerk, today I
gonna talk about Githubs and how we use it*；还有，「现在大家都用 coding agent 了，应该不会有手动操作
github 的部分」，要给出实际的交互。所以这一版：

1. **稿子是说话，不是念。** 开头先是那堆乱七八糟的便签（钩子），然后才是「嗨，欢迎来到 Novawerk 101」。
   借的是口气：对着一个人讲，一次只说一件事。不模仿任何人的声音。
2. **不教在 GitHub 上点按钮，教跟 agent 说什么。** 画面里是一个对话框：你打一句话（旁白说到哪，字就
   打到哪），agent 回你一张卡片（Issue 或 Pull request），然后才切到 GitHub 上看结果。
3. 仍然要自己做的只有进门那三步：注册账号、把用户名发给伙伴、在邮件里接受邀请；还有第一次让 agent
   连上自己的 GitHub 账号。

看完要会的事没变：**提需求和反馈**（开一条 Issue，在下面聊），**自己改文档、传材料**（一个 Pull
request，我们看过再合并）。讲概念只用半分钟：GitHub 是一个网站，像项目的共享文件夹加一块留言板，
谁改了什么都有记录；三个词（Repository、Issue、Pull request）。

## 能用的事实

- GitHub 的界面是英文的，片子里它的字都用英文原文，两个语言版本一样：标签 **Code**、**Issues**、
  **Pull requests**；状态 **Open**、**Closed**、**Merged**；PR 里的 **Files changed**；接受邀请的
  **Accept invitation**；注册的 **Username**、**Sign up**。前几项 2026-11-17 在 GitHub 网页上看过；
  **Files changed** 是凭经验写的，那天没有点开看。
- 两处为了短做的简化：注册只画了 Username 和 Sign up（真实表单还要邮箱和密码，最后的按钮是 Create
  account）；邀请邮件里的按钮是 View invitation，点开的页面上才是 Accept invitation，片子画成一步。
- **agent 是通用的对话框**（创始人选的），不是任何产品的界面：一个火花图标、「你的 coding agent」、
  一个输入框。旁白里点名「Claude Code、Codex 都行」，画面里这两个名字只作为便签出现一次。
  「连接 GitHub」那个按钮是示意：不同的 agent 连 GitHub 的方式不一样，片子只说「第一次让它连上你的
  账号，它会带着你」。
- agent 能不能做到片子里说的事（开 Issue、改文件、把文件放进仓库、提 Pull request）：
  - **在电脑上跑的 Claude Code 可以**，前提是装了 GitHub 的命令行工具并登录过、对仓库有权限、开在
    仓库的文件夹里。验证的范围只有这么多：这条片子自己的 Pull request，是开发者在一台早就配好的电脑上
    用 Claude Code 开的，里面的音频和图片也是这样提交的。这**不等于**一个不写代码的人从零走通过；
    装工具、登录、拿到权限那几步，片子没有演，也没有人按片子试过。
  - **Codex 没有试过。网页版 / 云端的 agent 没有试过**：贴进对话框的文件能不能落进仓库，各家不一样，
    这是片里最可能在别人那里做不到的一步。发给某个项目方之前，用他实际在用的那个 agent 把片里那两句话
    走一遍。
  - 片里那句话没说是哪个仓库。真实使用时，agent 要么开在仓库的文件夹里，要么先选好仓库；画面用对话框
    标题栏里的 `your-team / your-project` 表示「已经选好了」。
  - 片里 agent 回的卡片、编号（#13、#14）、仓库名、文件、人（「你」「宁」「周」，英文版 Me、A、J）
    都是编的，不对应真实项目和真实的人。
- 示范的那句话带着内容（「收费那条，改成不收费」），不让 agent 自己编答案。
- 片子让 agent「提个 PR，让大家先看看」，不让它直接改主线：让改动先被看一眼，是我们想要的协作方式。

## 两处风险判断（2026-11-17，总控审查时提的）

- **片里出现 Claude Code、Codex、GitHub 这些产品名。** BRAND.md 没有不许提别家产品的规则；片里只写名字、
  不用图标，说的是「都行」，不偏向哪一家，也没有链接。在小红书上会不会被当成推广，没有依据说会，也
  没法保证不会。判断：可以发；如果被限流，先怀疑这一处，把便签和旁白里的产品名拿掉再发。
- **「三步，开始」那个镜头**（注册账号、发用户名、接受邀请）是全片最像「引导去站外注册」的画面。
  为了不读成「加入 Novawerk」：示范仓库用占位的名字 `your-team / your-project`，不带我们的名字；邀请
  写成「邀请你协作」，接受后是「已接受」，不出现「加入」；用户名写成 `<your-name>`，一看就是占位
  （原来的 `your-name` 在 GitHub 上是个真实账号）。判断：这样可以发；它讲的是 GitHub 的账号，不是我们
  的成员。

## 不能说的（这条特有的）

- 不出现任何真实项目方、真实仓库里的内容。
- 不说 GitHub 是我们的，不用 GitHub、Claude、Codex 的图标；只写它们的名字。
- 「现在很多人手边都有 coding agent 了」是创始人的判断，照这个分寸说，不说成「所有人」。
- 第三条提醒按原意说：公开的仓库谁都能看，隐私和密码别放。

## 旁白

- 稿子在 `narration.ts`，也是字幕，中英各一份，段、行、短语一一对应（时间轴按位置找短语）。英文不是
  翻译，是照同一个结构重新写的。
- 合成用微软的语音（Edge 浏览器「朗读」背后的服务，通过 `edge-tts` 这个包；免费，不要密钥；创始人
  2026-11-17 提的）。**这是非官方的接口**：它是给 Edge 浏览器自己用的，第三方程序这样调用很可能不在
  微软许可的范围内，微软也可能随时让它失效。而且这 20 个音频已经进了这个 MIT 许可的公开仓库。同样的
  音色在微软 Azure 的语音服务里有官方接口和免费额度（要注册、要密钥），这两份稿子的字数远在额度之内；
  要不要换，由创始人定，在他定之前不动。`edge-tts` 用的是 7.3.1 版。脚本 `scripts/tts.py`，中文默认 `zh-CN-YunxiNeural`，英文默认
  `en-US-BrianMultilingualNeural`，可以用环境变量换。每段一个音频（`public/vo/<语言>/<段>.mp3`），
  每个短语的起始时间来自这个服务返回的逐词时间，写进 `voice.ts`。音频和 `voice.ts` 都提交了，重新渲染
  不需要联网。
- 语速比默认快一点：中文 +6%，英文 +4%（`scripts/tts.py` 里的 `RATES`）。
- 每段音频合成后量一遍响度，加一个固定增益，目标 −16 LUFS，下面压一个限幅。实测出来各段略低：中文约
  −17.0 到 −17.6 LUFS，英文约 −16.5 到 −16.7 LUFS。成片里人声再乘 1.1（`shots/parts.tsx` 的
  `VO_GAIN`），整片中文 −16.7、英文 −15.8 LUFS。
- `voice.json` 是脚本自己的记录（每段的时长和每个短语的起点）：只重做某几段时，其余段的时间从它读回来。
  片子用的是由它生成的 `voice.ts`。
- 发音只用语音识别反查过字句（中英两版都和稿子对得上），没有人逐句听过。
- 时间轴跟着旁白走（`timeline.ts`），每个语言一套：镜头长度是旁白说完的时间，再延到下一拍，所以切镜
  仍在 120 BPM 的拍子上。画面里的每个动作等的是旁白里对应的那个词；对话框里的字按旁白说那句话的
  起止时间匀速打出来。

## 视觉和声音

- **便签堆叠**（BRAND.md 的默认风格）：白底、墨黑边框的便签和窗口、绿色强调。一个画面一个强调色。
  Open 是绿色描边，Closed 和 Merged 是墨黑实心，不用 GitHub 的紫色和红色。你说的话是墨黑底白字，
  agent 的回答是白底。
- 配乐代码合成，C 大调（C Am F G），120 BPM，压在人声下面（`Root.tsx` 里半音量）。每次便签落下、
  打字、发送、agent 回答、关闭和合并都有音效。每个语言一份（`music.wav`、`music-en.wav`）。
- `kit/root.tsx` 为这条片子加了 `musicVolume`（默认 1，别的片子不受影响）。
- 渲染时踩过一个坑：第一版里一个对话框在成片的很多帧上面三分之一没画出来（单帧 `still` 是好的）。
  原因和查法记在 `../../README.md` 的 Gotchas 里。所以这一版里，卡片和窗口落定以后不再留着 `opacity`
  和 `transform`（`shots/parts.tsx` 的 `settle`、`drop`、`pop`）。出片前渲染两遍逐帧对比。
