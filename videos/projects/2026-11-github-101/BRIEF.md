# Novawerk 101 · GitHub 是什么，我们怎么用它 · 2026-11

Novawerk 101 的第一条：给**不写代码的项目方**看的讲解片，做成一首 60 秒的说唱。共用规则见
`../../BRAND.md`，这里只写这条视频自己的事。

- 起因（创始人，2026-11-17）：和项目方协作时发现，很多人不知道 GitHub 是什么，也不知道怎么操作。
- 给谁看：带着想法来的项目方和他们的伙伴，不写代码，第一次被邀请进一个仓库。
- 发在哪：直接发给项目方（微信等），放进 onboarding 材料；中文版也发小红书；英文版给不说中文的伙伴。
- 规格：**中文版和英文版各一条**，3:4（1080×1440），各 60 秒，说唱加字幕，不出 9:16。
- 因为要发小红书：画面、字幕、发布文案里**不放任何网址**，窗口的地址栏不画；不引导、不招人。
- 成片：`out/github-101_3x4.mp4`（中文）、`out/github-101_en_3x4.mp4`（英文）；封面 `out/cover_3x4.png`、
  `out/cover_en_3x4.png`；发布文案 `POST.md`。

## 为什么是说唱（创始人 2026-11-17 定的）

前两版都是「旁白 + 配乐」：第一版念稿子，第二版改成播客口气、换了微软的语音。创始人听完第二版说：
「感觉音乐和词不对劲，也许可以用 rap 的形式来做……单纯的 TTS 可能不够。」原因是旁白按自己的语速说，
配乐按自己的拍子走，两样东西没有关系。所以这一版：

1. **词和音乐是一起生成的。** 把要讲的内容写成押韵的短句，交给音乐模型，人声和伴奏一次出来，词就在
   拍子上。创始人听了中文、英文两段小样，说「听着挺好的」，成片用的就是那两段；后来只有中文歌的
   结尾按他的意思重做过（见「歌」）。
2. **只讲唱得进去的东西。** 60 秒装得下：乱在哪、GitHub 是什么、三个词、跟 agent 说一句、两个提醒。
   装不下的（注册账号、接受邀请、让 agent 连上 GitHub、Issue 要写清想要什么和为什么）放在发布文案里。
3. **画面跟着词走。** 每个镜头从这段词开唱前的那个八分音符切入，画面里每个动作等的是词里对应的
   那个字（`timeline.ts`）。
4. **像一支 MV，不是一页页列表。** 创始人看了方向后说：「不要全是列表，也许可以真的有个人在跳舞，像个
   mv 啥的」「画的就行，形式上没有任何要求，你来想想怎么能更好的科普和沟通，同时足够有趣」。所以：一个
   画出来的角色（后来定成一只河狸）从头跳到尾，动作卡在歌的拍子上；agent 是一个小机器人，跟它一起跳；正在唱的那句词就是
   画面的大标题，唱到哪个短语哪个短语变绿；三个词和两个提醒一次只上一个，不排成列表。

看完要知道的事没变：需求和反馈开成 Issue，改动走 Pull request、有人看过再合并；这两件事都可以让
coding agent 代劳。

## 歌

- 两首歌各约 60 秒（中文 60.11，英文 60.19），文件名 `public/song/zh.mp3`、`en.mp3`。**这两个文件不在这个仓库里**（见下面
  「许可和标注」）；生成它们的「计划」（每段的词和风格描述）在 `public/song/zh.plan.json`、
  `en.plan.json`。风格：松弛的 boom bap，90 BPM，男声，电钢琴和弦。
- 用的是 ElevenLabs 的音乐模型 `music_v2_5`，脚本 `scripts/song.py`。**同一份计划再生成一次会是另一首
  歌**，所以那两个文件就是原件，脚本默认不覆盖它们。
- **中文歌的结尾重做过。** 创始人看了成片后，把最后一句从「一起把想法，做成真的东西」改成「一起把
  想法，变成真的」。做法：让模型保留第一首歌的前 48.1 秒、只重新生成最后一段
  （`public/song/zh.ending.plan.json`）；模型交回来的前半段和原来很像但不是同一份音频，所以成片用的
  `zh.mp3` 是第一首歌的前 48.26 秒接上新生成的结尾，接缝在两句之间的空隙里（命令在 `scripts/song.py`
  的说明里）。接上之后前 48 秒就是创始人听过的那段音频（重新编码过一次 mp3）；48 秒之后的四句是新唱的，发给他
  听了。英文歌没有动。
- 词在 `lyrics.ts`，也是画面上的歌词，中英各一份，段和行一一对应；短语的切法大多相同，时间轴按位置找的那几个短语两边都有。英文
  不是翻译，是照同一个结构重新写的。
- 每个短语什么时候唱，来自 ElevenLabs 的强制对齐（`scripts/align.py` → `voice.ts`）；拍子是从音频里
  量出来的：中文 90.0 BPM，英文 88.7 BPM（模型没有完全照 90 来）。强制对齐的精度大约十分之一秒，
  同一段音频跑两次会差这么多，偶尔还会把一句的第一个字提前整整一秒放进前面的停顿里（重做结尾
  时中文第二句就这样错过，是对着成片看出来的）。所以中文歌只重新对齐了换过的最后两段
  （`align.py zh habits close`），前五段沿用第一次的结果；每次对齐之后都要对着歌看一遍成片。`voice.ts` 提交了，所以没有歌的
  文件也能看时间轴、出静帧；出成片要有那两个文件。
- 唱得对不对：用语音识别把两首歌（中文是接好之后的）转回文字，和词逐句对过，没有漏句。两处识别结果和词不一样：
  「Novawerk」两首都被识别成「NovaWork」；中文「三个词」被识别成「三个字」。创始人听过两首歌，说
  「听着挺好的」（那时中文歌还是原来的结尾；新结尾的四句他还没有回话）。
- 响度：歌本身中文 −12.9、英文 −13.4 LUFS，峰值接近满刻度；成片里中文乘 0.89、英文乘 0.93
  （`Root.tsx` 的 `SONG_VOLUME`），两条都在 −14 LUFS 左右。
- 歌上面不再叠音效。BRAND.md 的习惯是每个画面动作配一个声音，这条例外：动作落在词上，不一定落在
  拍子上，再叠音效会和节奏打架。
- 换歌之后先跑 `pnpm video 2026-11-github-101 music`（或直接 `all`）：`render` 只在没有 `music.wav` 时
  才生成它，否则会把旧的歌压在新画面下面。

### 许可和标注

- 歌是音乐模型生成的，受 ElevenLabs 音乐条款约束，不是我们合成的，也不在这个仓库的 MIT 许可之内。
  条款不许把生成的音乐放在别人可以下载去用的地方，所以**两个 mp3 不进这个公开仓库**
  （`videos/.gitignore`），由 Novawerk 成员另外保管；成片 `out/*.mp4` 带着歌，照常提交。
  `public/song/NOTICE.md` 写了这些。
- 在哪个平台发，就按那个平台的规定标注 AI 生成内容：人声和音乐都是。
- 账号套餐是否合适、歌的原件放在哪，这两件事由创始人定，记录在私有仓库，不写在这里。

## 能用的事实

- GitHub 的界面是英文的，片子里它的字都用英文原文，两个语言版本一样：三个词（Repository、Issue、
  Pull request）和状态 **Open**、**Merged**（2026-11-17 在 GitHub 网页上看过）。
- **agent 画成一个小机器人**，不是任何产品的界面或形象。这一版词里和画面里都不点名任何产品。
- agent 能不能做到片子里说的事（开 Issue、改文件、提 Pull request）：
  - **提 Pull request：在电脑上跑的 Claude Code 可以**，前提是装了 GitHub 的命令行工具并登录过、对仓库
    有权限、开在仓库的文件夹里。验证的范围只有这么多：这条片子自己的 Pull request，是开发者在一台早就
    配好的电脑上用 Claude Code 开的。开 Issue 用的是同一个命令行工具，但为这条片子没有单独试过。这**不等于**一个不写代码的人从零走通过；装工具、登录、拿到权限那几步，片子
    没有演，也没有人按片子试过。
  - **别的 agent、网页版 / 云端的 agent 没有试过。** 发给某个项目方之前，用他实际在用的那个 agent 把
    片里那两句话走一遍。
  - 片里那句话没说是哪个仓库。真实使用时，agent 要么开在仓库的文件夹里，要么先选好仓库。
  - 片里 agent 回的卡片、编号（#13、#14）、仓库名、文件、人（「你」「宁」「周」，英文版 Me、A、J）
    都是编的，不对应真实项目和真实的人。
- 「跟它说一句，Issue 就出现」是歌词的说法。实际上 agent 要先配好（见上），四份发布文案里都写了。
- 片子让 agent「提个 PR」，合并之前有人看：让改动先被看一眼，是我们想要的协作方式。

## 不能说的（这条特有的）

- 不出现任何真实项目方、真实仓库里的内容。
- 不说 GitHub 是我们的，不用 GitHub 或任何 agent 产品的 logo。（Open、Merged 前面的小符号是照
  GitHub 界面上的状态符号用我们的线条重画的。）
- 提醒按原意说：公开的仓库谁都能看，隐私和密码别放。

## 视觉

- **便签堆叠**（BRAND.md 的默认风格）：白底、墨黑边框的便签和窗口、绿色强调。副歌（三个词）和结尾是
  墨黑底。Open 是绿色描边，Merged 是墨黑实心，不用 GitHub 的紫色。
- **河狸和机器人**（`../../kit/dancer.tsx`，别的片子也能用）。跳舞的是一只围着绿围巾的河狸：Werk 是
  工坊，河狸是动物里的建造者。画法照成熟吉祥物的路子：一整块圆滚滚的身体，头身不分，四肢很短，五官
  极少，不描边，只留两颗白门牙和一条扁尾巴当记忆点；双手举起时门牙露得更多。创始人对这个角色定下的
  几条：
  - 毛是河狸本来的棕色，不要通体品牌绿。棕色不在 BRAND.md 的配色里，是为这个角色开的例外。
  - 品牌绿只在围巾上（黑底上是亮绿）。**不戴绿帽子**，以后的角色也一样。
  - **它是这条片子的角色，还不是定下来的 Novawerk 吉祥物**：要不要当吉祥物是另一个决定。

  之前试过的几个画法（火柴人、便签人、星星、萤火虫等）都没有用，也没有留在仓库里。动作是几组姿势
  （`shots/moves.ts`），每拍换一个，提前一点到位再停住，胯在拍子上往下沉、身体跟着压扁一点、尾巴跟着
  摆。机器人就是 agent，跟着拍子点头摆手，递东西时把手举起来。两个都不是任何产品的形象。
- **歌词是大标题**（`shots/parts.tsx` 的 `Lyric`）：正在唱的短语是绿色，唱过的是墨黑，还没唱的是灰色。
  片头和结尾不出歌词（片头画面上就是那几个字；结尾画面上是字标、101 和最后一句，「今天就到这」只在
  歌里）；副歌里三个词各自放大成画面主角，下面是唱的那半句，
  旁边一张便签用大白话再说一遍。
- 七个镜头（`STORYBOARD.md`）。歌一开口就是「Novawerk 一零一」，所以第一个镜头是系列标题，痛点在第二个
  镜头；小红书用作缩略图的首帧仍然是痛点镜头的最后一刻（`Root.tsx` 的 `poster`）。
- `kit/root.tsx` 为这条片子加过 `musicVolume`（默认 1，别的片子不受影响）。
- 渲染时踩过一个坑：第一版里一个对话框在成片的很多帧上面三分之一没画出来（单帧 `still` 是好的）。
  原因和查法记在 `../../README.md` 的 Gotchas 里。卡片和窗口落定以后不留 `opacity` 和 `transform`
  （`shots/parts.tsx` 的 `settle`、`drop`、`pop`）。出片前渲染两遍逐帧对比。
